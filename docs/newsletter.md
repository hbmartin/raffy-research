# Newsletter drafting

Report readers share newsletter settings and editorial actions in each Workspace. First enabling automation prepares published reports whose coverage overlaps the preceding 180 days, including historical citations inside those reports. Later settings saves only update settings. Disabling stops future automatic preparation; existing jobs finish and manual drafting remains available. Use **Prepare themes** for a fresh preparation and **Retry** for a failed attempt.

The app offers up to three themes, supported choices first. A selection snoozes its angle for thirty days; other angles remain available. Retry uses current settings and current evidence eligibility, retains the original report and selected angle, and links the new attempt to the previous failure. Older-report retries are supported. Abandoned or conflicting selections cannot be retried. Failed attempts remain failed and never automatically retry. A malformed candidate gets at most two repairs, is recorded and excluded when exhausted, and does not block other usable themes. Each draft shares two repairs across generation and audit failures. Each processing unit owns its repair feedback, which clears on success while failures remain in history. Repairs are reserved durably before dispatch; interrupted dispatched requests consume capacity, and interruption before dispatch does not. An exhausted count-two checkpoint never dispatches a third repair. Ambiguous legacy in-flight repair states require manual Retry. All counters survive resume.

Saved drafts retain their complete original article, style, evidence and audits. They remain immutable and exportable when evidence later becomes Junk, retracted or unavailable; the app shows warnings. History loads twenty entries at a time. Failed job summaries appear immediately; expand audit details to fetch audit passes, failing claim checks, repair counts, and rejected outputs. Polling does not load checkpoints. Failed revisions and their retries retain the previous saved draft and ready selection; attempt progress is shown separately. Possible duplicate evidence can be compared and confirmed or separated. The latest explicit Keep/Junk judgment applies to equivalent content. Retraction remains independent. A changed page at the same URL is a separate version. Identical normalized prose across URLs groups automatically only at forty or more words and excludes recognized complete error/paywall templates, never substantive headline prefixes such as “Forbidden fruit” or “404 ways.” Existing suggestions remain visible. Short cross-URL copies become suggestions; structured metrics remain independent judgments. Same-URL equivalent versions can share judgments. Base copy groups remain intact when a reviewed relationship is separated. Confirmed paths connect these groups; a conflicting separation returns its connecting confirmations. Reverse those decisions explicitly before proceeding. Splits restore each group's own latest explicit Keep/Junk judgment and recompute its representative and publication date, without creating judgments.

## Execution and deployment

Hosted generation uses the saved model and configured API authentication. Custom model names are retained; a supported adapter discovers its context limit, otherwise settings must declare it. Declared context remains separate from discovered limits, which are bound to provider and model. Changing either field clears the editable declaration. Hosted responses default to a configurable 16,384-token cap; new jobs pin that cap, while existing queued jobs keep 4,096 tokens. Prompt capacity is the pinned context minus the response allowance and a 2,048-token safety margin. Invalid combinations are rejected before enqueueing. Response-cap exhaustion records partial output and usage, immediately fails, and requires manual Retry after settings changes. It spends no automatic repair and never increases the allowance. Style patterns fold through resumable bounded aggregation, preserving literal house guidance and every previously identified rule ID and exact quotation. Evidence passages are deduplicated with their original IDs, authority assessments and counterevidence retained. If these required inputs still exceed capacity, the job explains how to change settings before Retry. The 64KB limit bounds processing batches only; complete generation and audit prompts use the actual pinned input budget, including instructions, articles, style, evidence and repair feedback. Candidate capacity failures are recorded and excluded without stopping other themes. Shared or draft capacity failures require Retry with actionable required/available sizes. Checkpoint version 3 stores style partitions, sample offsets and stable repair-unit identities. Legacy /20 and version-2 /3 partitions preserve completed ranges and saved notes; only unprocessed ranges split for serialized UTF-8 size, sharing their original repair allowance. Saved legacy patterns fold before samples leave the prompt. Completed repairs are recognized by saved outputs and cursor progress; positive historical counters alone do not block resume. Impossible cursors and ambiguous active repairs require Retry. Large evidence, style samples and topic libraries are processed in resumable batches with original source ids and exact passages. Required evidence is never silently truncated to make a prompt fit.

`/api/cron/newsletter` authenticates with `CRON_SECRET`. `NEWSLETTER_INVOCATION_SECONDS` controls both its Vercel route duration and runtime deadline: 800 seconds by default, with work draining until nothing is claimable or 640 seconds have elapsed. Hosted calls default to a 600-second timeout (`NEWSLETTER_HOSTED_TIMEOUT_MS`), leaving thirty seconds reserved for persistence. A request starts only when its entire timeout plus that reserve fits, with checks before repair reservation and dispatch. An invocation-budget yield spends no repair and ends draining. Startup and build reject incompatible execution settings. Local draining has its own `NEWSLETTER_LOCAL_WORK_SECONDS` window, defaulting to the greater of 900 seconds or `LOCAL_AI_TIMEOUT_MS / 1000 + 60`; local calls retain their 600-second default. Model and research calls receive the deadline and cancellation signal. One worker-owned invocation signal governs model, research, and subprocess work. Provider timeouts remain distinct. Successful responses are saved under the lease before deadline yields and consumed on resume without another call. Deadline expiry yields resumably; an interrupted final repair fails its processing unit. Exhausted candidates are recorded and excluded while other themes continue; exhausted drafts and shared batches require manual Retry. Lease loss retains its own error. Verify the generated `.vercel/output/functions` configuration when changing this setting. The global Vercel function duration remains `max`; newsletter alone has the explicit route override.

Jobs use a database clock, timezone-aware two-minute leases and thirty-second renewal. Execution is exclusive per Workspace across local and hosted workers. Every mutation requires its Workspace, token, running status and an unexpired lease. A worker that loses its lease cancels generation. Expired work resumes from checkpoints. Publication notification failures do not undo a successfully published report; a cheap reconciliation query recovers missing preparation jobs.

Personal execution requires `LOCAL_AI_OPERATOR_USER_ID` set to the authenticated app user's id. The worker checks that user's report-reader permission and claims only their local jobs. Other editors may select hosted generation or edit editorial settings and enqueue work for an unchanged local provider/model using server-stored allocation metadata; ownership stays with its operator. Client-supplied discovery and allocation metadata are ignored. Changing local provider, model or allocation requires verification in that operator’s local runtime. Configuration issues appear even without an enqueued job, and disabling automation remains available. Changing settings preserves queued jobs' runtime and owner. Legacy ownership is assigned only by explicit migration mapping.

Run `pnpm dev:evidence` for the local worker. It checks every fifteen seconds while the application is alive. Installed Codex and Claude binaries use native authentication; subscription tokens are never copied into application storage. The text adapter uses a temporary working directory, a minimal environment without application credentials, and explicit controls disabling tools, user/repository instructions, integrations, hooks and persistence. It capability-checks the binary before generation and rejects unsupported versions. See [Codex controls](https://learn.chatgpt.com/docs/config-file/config-reference) and [Claude CLI controls](https://code.claude.com/docs/en/cli-reference). Ollama newsletter execution requires an explicit `OLLAMA_NUM_CTX`. Its effective context is the minimum of the model limit, any declaration, and this operator ceiling. A queued job larger than the current ceiling fails clearly for manual Retry; the worker never silently overrides the allocation.

Pages poll every five seconds only while jobs are queued or running. Idle views refresh on focus, navigation, local actions or **Refresh newsletter**. Dirty settings survive refetches and untouched audience suggestions update.

## Migration and recovery

1. Stop ingestion, callback processing and all local/hosted newsletter workers; temporarily disable scheduled invocations. Set `NEWSLETTER_WORKERS_PAUSED=true` in every running instance.
2. Supply the target `DATABASE_MIGRATION_URL` explicitly. For legacy local work, create a private JSON mapping of Workspace id to app-user id and supply its path as `WORKFLOW_OPERATOR_MAPPING_FILE`. Unmapped local jobs remain unclaimed; ownership is never guessed.
3. Run `pnpm db:migrate:workflows`. It writes a compressed recoverable snapshot under `.local-ai-runs/migration-snapshots` with owner-only permissions before applying additive migrations through 0018. Existing migration files remain unchanged. Do not commit or share that snapshot: it contains database payloads and authentication data.
4. Historical confirmed paths and separations are preflighted. Contradictions abort the backfill with the blocking decision IDs; resolve them explicitly instead of guessing a grouping. The command rebuilds deterministic base copy keys and effective memberships, normalizes queued/interrupted mutable checkpoints to version 3 without resurrecting failed attempts, preserves existing operator mappings and pinned legacy response allowances, and backfills capture/version indexes, observations, judgments, equivalence groups, draft/offer/attempt/failure history and publication ledgers. It preserves all original capture and report columns, IDs, dates and saved draft payloads and every existing history payload. Count and payload-hash verification runs inside the backfill transaction; failure rolls back the backfill and keeps the snapshot. Legacy combined-publication attempts remain recorded, and linked ledger entries prevent duplicate automatic preparation.
5. Keep the snapshot and logged digest. Restore into a separate empty database from its JSON table payloads using PostgreSQL `jsonb_populate_recordset`, loading parent tables before dependent tables, then compare row counts and payload hashes before switching the application. The additive schema migrations need not be reversed to restore legacy payloads.
6. Confirm operator mappings, model budgets and recent history, remove the pause flag, and resume ingestion and scheduled workers.

Do not use plain `db:migrate` as a substitute for this preservation/backfill workflow on a database with existing newsletter/capture history.

## Verification

Automated tests use deterministic model and subprocess fixtures, including environment/file canaries, and never spend provider credits. Integration tests prefer a disposable native PostgreSQL cluster (`TEST_POSTGRES_BIN` may specify the binary directory); otherwise the ordinary lightweight fixture uses a single connection. True multi-connection transaction and non-UTC-clock verification requires PostgreSQL. E2E fixtures require a supplied loopback `E2E_DATABASE_URL` and use real local persistence. Test artifacts and reviewed visual baselines cover authenticated desktop/mobile interactions and downloads.
